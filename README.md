# Автоматизация бизнес-процессов: Google Apps Script + Sheets

Портфолио Алексея Азерьера — специалиста по автоматизации бизнес-процессов.

Здесь фрагменты **работающих в продакшене** решений, которые я спроектировал и внедрил
в производственно-строительной компании (быстровозводимые модульные здания).
Это не учебные примеры: код обслуживает реальные процессы предприятия.

> **Код обезличен.** Реальные ID таблиц, адреса, внутренние IP и секреты заменены
> заглушками вида `PUT_..._HERE`. Секреты в исходном контуре и так не хранятся в коде —
> они лежат в Script Properties, что видно по самим фрагментам.

## Кейсы

| # | Задача | Решение | Результат |
|---|---|---|---|
| [01](01-write-proxy-hmac/) | Веб-приложение обязано работать «от имени пользователя» (иначе в него попадал аноним), но тогда запись в базу идёт от того, у кого нет прав на файл. Дать права = сломать защиту | Отдельный доверенный прокси записи: пакет подписывается **HMAC-SHA256**, прокси доверяет подписи, а не сессии. Анти-replay по времени и по `txId`, сравнение подписи за постоянное время | Разделение привилегий: пользователь пишет в базу, не имея к ней доступа. Подделать автора или пакет без общего секрета нельзя |
| [02](02-event-sourcing-gateway/) | Данные проекта вносят 7 ролей параллельно; при обычной перезаписи ячеек теряется история и непонятно, кто что менял | Архитектура на **событийном журнале**: append-only `tx_journal` + пересбираемая витрина `view_current_state` (последняя запись на ключ) | Полная история «кто / что / когда / чем перекрыто», восстановимое состояние, идемпотентность по `txId`, защита от конкурентных записей |
| [03](03-role-model-field-level/) | Разные роли отвечают за разные **поля одной формы**, а не за разные экраны. Прав «на экран» недостаточно | Ролевая модель **на уровне отдельных полей**, вынесенная в справочники: матрица «роль × параметр». Два барьера — фильтр видимости и серверная проверка на запись | Новая роль или перераспределение полей делается строками в таблице, **без правки кода и редеплоя**. Клиентскую подмену ловит серверный барьер |
| [04](04-vor-monitor/) | Снабжение вручную сверяло графики поставки на предмет новой номенклатуры — рутина, позиции терялись | Планировщик обходит отслеживаемые книги, сравнивает со снимком состояния и шлёт **письмо-дайджест** только по изменениям. Есть веб-форма постановки на отслеживание | Ручная сверка заменена авто-мониторингом. Ничего не пишет в чужие книги — только читает, весь стейт в своём хранилище |

## Стек, который здесь видно

**Google Apps Script (JavaScript)** · **Google Sheets как база данных** · HTML Service ·
Web App / REST · **HMAC-SHA256**, constant-time сравнение, анти-replay ·
event sourcing, витрины, идемпотентность · LockService (конкурентность) ·
CacheService (кэш справочников, TTL + инвалидация) · ролевая модель, НСИ-справочники ·
триггеры-планировщики, почтовые дайджесты

За рамками этого репозитория, в рабочем стеке: **Python**, **Bitrix24 REST**,
1С (консультирование), SQL/PostgreSQL, Docker, Git, LLM и эмбеддинги.

Решения **спроектированы и внедрены мной**: сбор требований у бизнеса, модель данных

и почему именно так.
